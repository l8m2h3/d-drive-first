# C 盘写入报告模板

R5 要求：写入发生**之前**，用五项事实让用户自己判断。缺一项就补一项，不要只写「我要写 C 盘，可以吗」。

下文用 `$DROOT` 指工作根，默认 `D:\APP`。

## 模板

```markdown
计划写入 C 盘，预检如下（只读，尚未写入）：

1. 完整路径：`C:\...`
2. 原来是否存在：否 / 是
3. 现有占用：不存在 / 1.24 GB（1,332,341,760 字节）
4. 预计新增：250 MB（262,144,000 字节）
5. 必须放 C 盘的原因：<工具 X 把路径硬编码在 %LOCALAPPDATA%，无可配置项；
   已尝试 --cache-dir 与符号链接，均不生效>
   D 盘替代方案：<已评估：$DROOT\...，因为 Y 不可行>

是否继续？
```

## 示例：可安全改到 D 盘（不要报告，直接改）

任务：`pnpm install`。
处理：`pnpm config set store-dir $DROOT\.cache\pnpm-store`，在 D 盘项目目录里安装，C 盘新增 0 字节。这属于 R4，不需要 R5 报告。

## 示例：确实只能写 C 盘

任务：某安装器强制解包到 `C:\ProgramData\<Vendor>\cache`。
报告：给出五项，并说明「安装完成后可删除缓存目录」，等用户同意。

## 示例：D 盘空间不足

报告里把第 5 项换成空间事实：`D: 剩余 1.8 GB < 预计新增 6 GB`，并给出选项——清理 D 盘 / 换一块盘 / 分段写入 / 经同意后写 C 盘。

## 措辞要求

- 用绝对路径，不给相对路径。
- 容量同时给易读值和字节数。
- 原因写具体机制（哪个变量、哪个默认值），不写「因为默认这样」。
- 已尝试的替代方案要列出来，避免用户重复建议。
- 报告一次即可；用户明确要求放 C 盘后不再重复劝阻。
